# SchoolCalc exact CLI UX cases

Each numbered Markdown file is one self-contained, exact-emulation UX case.
It is generated by [`ti86.cli.mjs`](../../ti86.cli.mjs) with `--case-id`, so it
contains the digest-pinned release, full replay command, ordered keystrokes and
waits, and every captured 128×64 LCD screen in one reviewable artifact. These
are not a JavaScript simulation: each replay transfers the complete release to
MAME's TI-86 through its virtual Graph Link and launches `ASCHL` through
TI-OS.

| Case | Experience under review |
| --- | --- |
| `01-cold-picker` | First boot and the unconfirmed learner picker |
| `02-picker-navigation` | Focus movement across the picker without a screen rebuild |
| `03-subject-navigation` | Nonzero Subject route, named removal request, and safe Cancel |
| `04-profile-progress-switch` | My Progress, user switching, and return to Subjects |
| `05-math-notes-scroll-back` | Long study notes, `NEXT`/`END`, and reader Back |
| `06-math-examples-steps` | Worked-example pacing and return from a learning module |
| `07-math-quiz-result-qr` | Direct answer keys, local result queue, and result QR |
| `08-science-notes-scroll` | A second subject's reading flow and dense terminology |
| `09-history-quiz-result-qr` | Subject-neutral quiz behavior with non-math content |
| `10-pokemon-quiz-result-qr` | One-module auto-skip and six-question quiz through QR receipt |

The currently refreshed release cases are `01`, `03`, `04`, `05`, `07`, `09`,
and `10` for `caacecbbb8b6`. Case `07` deliberately ends with `2nd` + EXIT so the
CLI can retrieve and CRC-validate the private `DSQOUT`/`SCO1` receipt created
by `MARK`; Case `09` takes `LATER` and proves the Result remains queued. The
remaining named cases are retained replay fixtures and must be regenerated
before a full-release claim.

Review these as a learner rather than as a test engineer. In particular, call
out any missing orientation, unclear verb, unexplained wait, hidden state,
ambiguous label, non-obvious key, or screen that requires prior knowledge of
SchoolCalc internals.
