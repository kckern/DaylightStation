# Daylight Station identity and access

The design defines who can use each surface, which actions they can take, and whose data an app can read or change. It includes the application access matrix, browser sign-in and recovery states, and household administration workflows. [Read the design](superpowers/specs/2026-11-26-identity-and-access-design.md).

## Implementation plans

Start with the foundation plan for the shared interfaces and rollout order. The four tracks use those interfaces.

| Plan | What it covers |
|---|---|
| [Foundation and rollout](superpowers/plans/2026-11-26-identity-and-access.md) | Household membership, scoped data, sessions, server enforcement, migration and cutover |
| [Browser apps, Admin and room displays](superpowers/plans/2026-11-26-identity-and-access-surfaces.md) | Login gates, viewer-specific API responses, Home controls, room displays and the Identity & Access section in Admin |
| [Household kiosks](superpowers/plans/2026-11-26-identity-and-access-kiosks.md) | Login-free Piano, School and Fitness participation, guest activity and one-action biometric approval |
| [Policy assignments](superpowers/plans/2026-11-26-identity-and-access-policies.md) | Content Filter and State Gates rules for people, roles and rooms, with preview and activation |
| [Services, devices and live events](superpowers/plans/2026-11-26-identity-and-access-services.md) | Device credentials, Telegram delegation, provider callbacks, subscriptions and background jobs |
