# DDD Compliance Decision Register

> Authoritative record of the architecture rulings (D1–D7) made during the DDD compliance remediation. These are FINAL — record them, don't re-debate. Source analysis: [`docs/_wip/audits/2026-07-06-ddd-layer-compliance-mega-audit.md`](../../../_wip/audits/2026-07-06-ddd-layer-compliance-mega-audit.md). Execution plan: [`docs/_wip/plans/2026-07-06-ddd-compliance-remediation-plan.md`](../../../_wip/plans/2026-07-06-ddd-compliance-remediation-plan.md).

Each ruling below is referenced from the layer guideline docs as `Decision D#`. When a task references a Decision, the ruling here is settled and not up for re-litigation during execution.

| ID | Question | Ruling | Rationale (one line) | Date |
|----|----------|--------|----------------------|------|
| **D1** | May application Containers import concrete adapters? | **No.** Containers never import concrete adapters — no exceptions. Bootstrap injects them. | The Container is the wiring seam, not the composition root; importing adapters couples the app layer to `1_adapters/`. | 2026-07-06 |
| **D2** | May `3_applications` import `1_rendering`? | **No.** Applications depend on a presentation/rendering port; composition injects the renderer implementation. This supersedes the original provisional allowance. | Rendering is a peer outer implementation layer. Direct imports make application orchestration depend on presentation mechanics and contradict the layer direction enforced by the audit. | 2026-08-28 |
| **D3** | Where do ports live — domain or application? | Ports live in `3_applications/*/ports/` **only**. Existing `2_domains/*/ports/`, including `ILifelogExtractor`, have migrated. | Ports express what the *application* needs from outside; the domain is pure logic with no external dependencies. | 2026-07-06 |
| **D4** | What is the SSOT for pure time helpers? | `2_domains/core/utils/time.mjs` is the SSOT. `0_system/utils/time.mjs` becomes a thin compat re-export. Hardcoded LA default stays for now. | Pure time math is domain-foundation logic; one source avoids drift between two copies. | 2026-07-06 |
| **D5** | May `3_applications` use `#system/utils/FileIO.mjs`? | **Banned** in `3_applications`. Data operations go through datastore ports. | The app layer must not know storage mechanics; enforced by the `apps-no-fileio` audit rule. | 2026-07-06 |
| **D6** | How is the domain hierarchy table scoped, and where does `content` sit? | The level table is extended to cover **every** domain folder. `content` is promoted to **Level 1 (shared)**, making the two peer imports (fitness→content, barcode→content) legal. | `content` is a cross-cutting capability consumed by multiple feature domains, not a peer feature. | 2026-07-06 |
| **D7** | Must adapters `extends` their port when one exists? | **Yes** — where a port file exists, flagship gateway/datastore adapters MUST `extends` it. Zero-importer port files are deleted, not kept as aspiration. Internal helpers/parsers are exempt. | An unimplemented port is dead documentation; enforcing `extends` keeps the contract real. | 2026-07-06 |
| **D8** | Which timezone do the `nowTs*` system time helpers format against? | `nowTs` / `nowTs24` / `nowDate` / `nowMonth` format against **DEFAULT_TIMEZONE** (household default, currently `America/Los_Angeles`), **not** a configured `system.timezone`. Persisted timestamps (log keys, entry dates, filenames) will not follow a changed `system.timezone`. Decoupled from configService in P1.7 (S-4). Inert while `system.yml` timezone == LA. | Removes a config-singleton dependency from the system layer; if a configurable tz is needed, thread it from callers. | 2026-07-07 |
| **D9** | Does canonical `deepMerge` let a `null` override clear an inherited base value? | **No.** `deepMerge` treats a `null` override as a no-op for keys already present in base (`over ?? base` — null loses to the existing value); it cannot clear inherited values. A null override only lands for keys NOT present in base. If clearing is needed, a dedicated helper must be added. | Behavior verified safe (emulator + loadAgentConfig both want null-loses); no config relies on null-clearing. | 2026-07-07 |
| **D10** | May production code outside `0_system` import Node `fs` directly instead of `#system/utils/FileIO.mjs`? | **No. Zero exceptions and no grandfathered baseline.** All production filesystem operations go through FileIO-backed adapters; API, application, domain, rendering, and composition code receive semantic capabilities. Enforced on every commit by the full-tree AST filesystem-import gate. | FileIO's own header already said it ("NEVER use direct fs.* calls outside of this file"). On 2026-08-26 `YamlLessonCompanionStore` corrupted a child's lesson-companion record with an async read-modify-write over a bare `fs.writeFile`, while `saveYamlToPathAtomic` — which prevents exactly that — sat unused in FileIO. Bypassing the layer is how the fix that already exists goes unfound. | 2026-08-25 |
