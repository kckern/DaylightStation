# Managed Media Preparation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce validated playback renditions only when a known-risk or failure-triggered assessment establishes that ordinary playback needs help.

**Architecture:** Durable preparation jobs and readiness evidence are separate aggregates. Application workers coordinate source access, capacity and conversion ports; file/process adapters inspect and transform media and publish artifacts atomically. Prepared candidates feed the selection contract from plan A.

**Tech Stack:** Existing Node ES modules/Vitest, YAML/FileIO, FFmpeg/ffprobe as injected process tools, existing HLS renderer.

**Spec:** [Design](2026-09-19-adaptive-playback-design.md); [execution index](2026-09-19-adaptive-playback-implementation.md); [control contracts](2026-09-19-adaptive-playback-a-control.md).

## Global Constraints

Inherit the index constraints. Originals are never modified. Source references
are opaque outside infrastructure. No bulk work without explicit storage quota
and reserve. Playback has priority over preparation. A produced file is not
ready until validated. A source revision change invalidates its old readiness.

## Review Focus

Source replacement mid-job (B1/B3), subtitle/HDR loss (B2), killed worker leaving
partial files (B3), eviction racing an active player (B3), repeated recruitment
events creating duplicate jobs (B1/B4) receive explicit tests below.

### Task B1: Preparation jobs and readiness evidence

**Files:** Create domain `PreparationJob.mjs`, `ReadinessEvidence.mjs`;
ports `IMediaPreparationGateway.mjs`, `IPreparationJobRepository.mjs`,
`IRenditionArtifactGateway.mjs`; implement A4's existing `IReadinessRepository.mjs`;
adapter preparation `PreparationStateStore.mjs` and matching tests.
Wire the real readiness repository into A4 use cases in composition without changing signatures.

**Interfaces:**

```js
// PreparationJob: {jobId,key,version,sourceRef,sourceRevision,profileKey,
//   trackSelection,engineVersion,state,progress,workerLease,artifactRef,failure}
// state: queued|preparing|validating|ready|failed|cancelled|superseded
// readiness key: {sourceRevision,renditionId,profileKey,evidenceVersion}
// Evidence: {key,validatedAt,expiresAt,checks,artifactRef,state}
// IMediaPreparationGateway
request({sourceRef,sourceRevision,profileKey,trackSelection,engineVersion})
status({jobId})
cancel({jobId})
// results: unsupported|queued|preparing|ready|failed|cancelled
// IPreparationJobRepository
get(jobId); findByKey(key); compareAndSet(jobId, expectedVersion, next); listPending();
// IReadinessRepository
find({sourceRevision,profileKey}); save(evidence); invalidate({sourceRevision,artifactRef});
// IRenditionArtifactGateway
inspectSource({sourceRef}); allocate({jobId}); validate({artifactRef,expected});
publish({artifactRef,sourceRevision}); pin({artifactRef,attemptId});
unpin({artifactRef,attemptId}); evict({artifactRef}); usage();
```

Artifact references remain opaque. Implement repositories using the atomic state
machinery from A3, with separate aggregate files and version checks. Job identity
is a stable hash generated by infrastructure from canonical source revision,
profile, tracks and engine version, not the signed URL.

### Task B2: Inspection, conversion and output validation adapters

**Files:** Create adapter preparation `ProbeMedia.mjs`, `BuildEncodingPlan.mjs`,
`FfmpegPreparationAdapter.mjs`, `ValidateRendition.mjs`, matching tests;
`tests/fixtures/adaptive-playback/generate.mjs` for tiny deterministic media files.
Reuse existing subprocess infrastructure where it meets deadline/cancellation needs.

**Interfaces:** `probeMedia({sourceRef, signal})` returns normalized source facts;
`buildEncodingPlan({source, profile, tracks, outputRef})` returns process argument
arrays and expected characteristics; `FfmpegPreparationAdapter.run({job, signal,onProgress})`
returns `{kind:'produced',artifactRef,expected}` or failure; `validateRendition`
returns `{kind:'valid',checks}` or `{kind:'invalid',reason}`.
Source resolution and path allowlisting occur inside injected infrastructure.

```js
it('writes only to the allocated artifact directory', () => {
  const plan = buildEncodingPlan({source,profile,tracks,outputRef});
  expect(plan.outputs.every(path => path.startsWith(outputRef.directory + '/'))).toBe(true);
  expect(plan.outputs).not.toContain(source.path);
  expect(plan.shell).toBe(false);
});
```

### Task B3: Scheduling, resource priority and artifact lifecycle

**Files:** Create application preparation `RunPreparationJob.mjs`,
`ReconcilePreparation.mjs`; adapters `RenditionArtifactStore.mjs`,
`PreparationWorker.mjs` in preparation; corresponding tests. Create composition
`backend/src/5_composition/modules/mediaPreparation.mjs` and its test.

**Interfaces:** `RunPreparationJob.execute({jobId})`,
`ReconcilePreparation.execute()`; worker injected with repository, capacity,
encoder, artifacts, readiness, clock and event publisher. Artifact store implements
B1 port. Playback source gateway sees ready artifacts through injected artifact
resolution, not an import of the preparation adapter.

- [ ] Add restart/pin/eviction/quota tests, including source replacement during encode:

```js
it('does not publish a rendition after its source changed', async () => {
  const run = worker.execute({jobId:'j1'});
  sourceProbe.revision = 'r2';
  encoder.finish({kind:'produced',artifactRef:'temporary:1',expected});
  await run;
  expect(artifacts.publish).not.toHaveBeenCalled();
  expect((await jobs.get('j1')).state).toBe('superseded');
});
```

Also race artifact pin against eviction under the same durable lock. An active
reader must win or receive a failed pin before opening; no unlink-under-player.

- [ ] Run `npx vitest run backend/src/3_applications/content/preparation backend/src/1_adapters/content/preparation/RenditionArtifactStore.test.mjs backend/src/5_composition/modules/mediaPreparation.test.mjs` red.
- [ ] Implement one preparation worker initially; jobs claim a 45s lease renewed every 10s. Capacity reservations use A3 with background priority. Active playback pressure cancels the worker safely when pause is unsupported and requeues checkpointable work. Bound repeated failure to three attempts with 30s/2m/10m backoff; corrupt sources stop immediately. Recheck source revision before publication. Use scoped temporary paths, atomic rename on the same filesystem, and manifests pointing only to complete artifacts.
- [ ] Implement quota/reserve validation and LRU eviction of unpinned derivatives. Maintain per-attempt pins with lease/reconciliation; never use filename patterns as ownership proof. Invalidate readiness durably before/with deletion reconciliation. Reserve worst-case output bytes before encoding, stop on reserve breach, and surface disk-full without damaging originals. Restart reconciles jobs, partial artifacts and external process ownership before admitting more work.
- [ ] Run crash injection, quota and concurrency tests green, commit `feat(preparation): schedule bounded jobs and manage rendition storage`.

### Task B4: Selective recruitment screening, playback triggers and user status

**Files:** Create application preparation `AssessMediaReadiness.mjs`,
`ScanMediaReadiness.mjs`; application port `IMediaRecruitmentGateway.mjs`;
adapter preparation `RegistryMediaRecruitmentGateway.mjs`; matching tests;
modify composition `mediaPreparation.mjs`, `adaptivePlayback.mjs`,
frontend `PlaybackStatus.jsx`; create `cli/playback-readiness.cli.mjs` and
`docs/reference/player/adaptive-playback.md`.

**Interfaces:** recruitment gateway `scan({cursor,limit})` returns
`{items:[{contentId,sourceRef,sourceRevision}],nextCursor}` or unsupported;
`AssessMediaReadiness.execute({contentId, clientProfiles, priority, trigger})`;
`ScanMediaReadiness.execute({limit:50})`. Existing ingestion/provider events call
the A0 policy with available metadata and invoke the assessor only on a risk match.
`trigger` is `{kind:'seed-risk'|'learned-risk'|'repeated-interruption'|'definitive-failure'|'manual',evidenceIds}`.
The opt-in cursor scan screens cached metadata only and catches missed risk matches.
CLI supports
`inventory`, `status`, `assess --content-id`, `scan --limit`, `cancel --job-id`.
Inventory/status are read-only; scanning/assessment writes require explicit flags
in CLI and the enabled household configuration.

- [ ] Test no assessment/probe/job for ordinary recruited media, missing metadata or audio-only sources; a risk match triggers assessment but not automatic conversion. Test exactly one assessment after the second distinct episode, repeated recruitment events, provider without enumeration, requested-item priority, a usable original during preparation, cancellation of viewer intent and automatic start only for a still-current waiting intent:

```js
it('does not start a completed preparation after the viewer left', async () => {
  await closePlayback.execute({intentId:'i1'});
  await preparationCompleted({jobId:'j1',contentId:'source:item'});
  expect(source.open).not.toHaveBeenCalled();
});
```

Build the event handler through composition so this exercises actual wiring.

- [ ] Run assessor/scanner/composition/frontend tests red.
- [ ] Wire new media and source revisions into cheap A0 screening using supplied metadata. Only a seed/learned risk match invokes background assessment; unknown/unflagged sources proceed normally. Runtime repeated-interruption/definitive-failure triggers reach the same deduplicated assessor. Require assessment evidence before scheduling conversion; compatible results cache a successful path without producing derivatives. Derive targets from the actual fleet. Keep library screening opt-in, cached-metadata-only and limited to 50 items per tick with a persisted cursor. Retry transient scan failures without advancing the cursor. Sources without enumeration remain assessable after playback triggers. Retain originals while viable; merge prepared candidates when available. Show actual progress with no invented ETA. Cancel viewer waiting intent when they leave, not another viewer's shared preparation job.
- [ ] Register configuration through existing config conventions: enabled flag, artifact root, quotaBytes, reserveBytes, profile settings, worker concurrency=1, and fleet profile IDs. Reject enabling with absent quotas; do not invent production disk allocation. Extend the existing configured admin interface or CLI to set values; do not add config file I/O in applications.
- [ ] Run tests green and index architecture/composition gates. Commit `feat(playback): prepare recruited media and resume waiting viewers`.
