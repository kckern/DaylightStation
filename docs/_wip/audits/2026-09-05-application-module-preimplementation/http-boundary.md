## Loading and dependency constraints

Production consumers already import the index and load all three leaves. Three
existing leaf-importing test files gain the aggregate closure after retargeting:
the string-error, request-logger and device-identity tests. Their loading changes
require explicit verification; do not describe all loading behavior as unchanged.

The original resolved-source closure contains 21 files. Its `uuid` package edge
uses the current backend scope in the inventory, and the proposed manifest
retains the backend's declared range. A require-condition projection is not
native ESM, clean install, lockfile or dependency-instance proof. Preserve the
canonical InfrastructureError class and the logger/dispatcher instance graph.

Logging now has a separate [selected boundary](logging-boundary.md) for
`logger.mjs`, `dispatcher.mjs` and `localTimestamp.mjs`, not an implicit approval
of the broad logging index:

- Two HTTP module-created loggers have sampling state; the logger module captures
  runtime hostname. Calls look up the dispatcher at call time, not construction.
- Any `LogDispatcher` constructed with a timezone changes module-global timezone.
  `resetLogging` does not clear that timezone and flushes without awaiting.
  Reinitialization replaces the dispatcher without disposing the old one.
- Logger timestamps default to runtime timezone; dispatcher timezone applies
  when an event has no timestamp. Neither behavior becomes the D8 `nowTs`
  household default or D4 pure time SSOT during relocation.
- The current logging index re-exports reset/configuration/transport utilities.
  It is not one of these four HTTP files. The logging specification selects its
  gated retirement (zero current source callers) and a separate test-only entry;
  actual semantic caller enforcement and full candidate proof remain required.
