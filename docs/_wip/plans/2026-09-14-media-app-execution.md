## Global constraints

- Demonstrate a behavioral failure before changing implementation; preserve working behavior with regression tests.
- Validate interaction → destination → command → actual player → returned state → accurate UI and feedback.
- Office screen is the only authorized physical test screen. Browser contexts may simulate additional screens. Preserve/restore office state; do not disturb other kiosks.
- P0 first, then P1/P2. Minimum undo moves into P0; expires 10 seconds after tap, cancels pending dispatch, returns live sources to live. Cross-device restoration and notes remain P1.
- Keep the bridge-owned media node stable across navigation; Content modules never import Media modules.
- Structured logs, design-system tokens, existing local/remote controller seam, additive API compatibility.
- Root agent owns tracking docs and end-to-end harness. Task workers own only their named implementation scope. Do not spawn subagents from workers. Commit only owned files; do not deploy from workers.

## Task 4: Shared item actions, receiver queue parity and minimum undo

Read handoff Step 3, RQ-PLAY-01–07, RQ-FIND-09/10 and taxonomy PLAY.1a/1b/2a/3a/5a/6a/7a, FIND.8a/8b, PLACE.3a/3b and RELY.4a. Later P1/P2 surfaces must consume this contract rather than inventing verbs. Keep Content props additive and independent of Media imports. Opening a collection or Details must not start playback; cameras/single photos show locally with an explicit Show on… alternative. Preserve the current view when starting playback.

Single-item Play starts now with `clearRest:false`; collection Play replaces in natural order with shuffle off; collection Shuffle replaces and turns shuffle on. Respect known unfinished-part information without pretending P1 household spot resolution is complete. Play next uses order-added semantics (`addUpNextMany` today); repeated additions preserve their order. A press-and-hold secondary action offers At the very front (`playNextMany` today), with a keyboard-accessible equivalent. Add to queue appends naturally ordered items without interrupting current playback. Every applicable item/collection has these verbs plus explicit one-off Play on… / Add to queue on… and Details. One-off selection leaves the shared aim unchanged and uses its remembered stop-or-keep preset. Confirmation names item/collection, destination, count/position and actual outcome. Preserve exact-attempt retry semantics from Task1.

Support local and screen receiver add, reorder, remove, jump and clear through their actual playback owner; command receipt alone cannot be reported as successful application. Verify the resulting queue and actual continuing/changed playback. Do not claim success for unsupported operations: return an unavailable reason and show it. Guard repeated Play on the same target while startup is pending; emit one start and show Starting on <screen>… on the initiating item. Cover both local and remote paths, with explicit retry still possible after failure.

Minimum undo is P0 by user decision: replacing playback, removing an item and clearing a queue offer Undo for 10 seconds measured from the original user tap, not from acknowledgment. Capture prior item, actual position, queue and playback/config state before mutation. Undo during pending wake/load must cancel that attempt and prevent late responses or delivery from starting it. Undo after application restores the affected screen's previous item/position/queue; a live source returns to live edge rather than a stale position. Never undo newer unrelated playback; compare the operation/playback identity at the applying owner. Cross-device access to Put it back and screen notes remain P1, but origin-device undo of a remote action is in this minimum slice. Expiry/cancellation seams must be compatible with Task8 rather than implemented as a toast-only timer. Starting fresh remains confirmed, not presented as reversible.
