# HTTP readiness evidence inventory

The source manifest at `tests/readiness/application-modules/http-source-inventory.json` compares main source commit `16a0f157f1` and owner-tree commit `7c0936d1b5`. Main `27e7b58a68` adds only a deleted-branch documentation entry. This is static declaration evidence, not a complete mounted-route inventory or a claim of coverage.

Each snapshot contains 1,176 literal route declarations across methods. The 657 explicit GET candidates comprise 647 declarations with literal paths and 10 with nonliteral paths; there are zero explicit HEAD declarations in the scanned scopes. Express may expose implicit HEAD behavior; that is not expanded here. Both snapshots contain 147 unresolved mount/middleware/dynamic records. The 83 literal v1 route-map entries still depend on `routers[key]`, installed providers, nested mounts and guards. Counts do not establish behavior parity. File hashes, line locations, local guard expressions and canonical owner paths are retained.

`http-case-inventory.json` contains 16 reviewed candidate cases across auth, config, catalog, School, Piano, Fitness, Media, admin/files, Feed, Health, Finance and Home. All remain explicitly blocked for full-app execution: fixture, identity, inherited middleware and response contracts are not yet complete. Existing School/ePaper drivers prove local mounted Express behavior using real IncomingMessage/ServerResponse with synthetic services; they do not prove the complete installed application or its authentication pipeline. Related receipt paths are references, not coverage credit for untraced routes.

GET is not assumed safe: Home TV GETs command devices; Fitness receipt-print GET prints; Plex stream GET mints playback state; catalog streaming GET is provider-backed SSE. Untraced services may refresh caches, perform provider IO or change state. Unknowns are represented as null/unknown, never silently permitted. Literal status/header snippets describe local branches, not a full response contract.

Before full-app coverage is claimed, boot `createApp` with a reviewed isolated synthetic configuration, enumerate actual nested Express mounts and middleware order plus `serverRequestHandler` liveness behavior, then issue requests through that assembled application. Use enabled/absent provider fixtures and anonymous/authenticated/denied identities. Do not import `serverMain` outside confinement: its config, dotenv and logging startup have effects. Match request parameters, expected status/headers/body/order and named successful receipt evidence case by case. Live household data, printer/device delivery and nonlocal providers are not authorized by this inventory.

The runtime comparator/schema is maintained separately. No tests, boot, network, merge or runtime execution was performed to create these inventory files.

Current execution evidence supersedes the initial static-only checkpoint: see [the mounted inventory](2026-10-10-application-modules-mounted-readonly-inventory.md) and [coverage ledger](2026-10-09-cutover-coverage.json). Three actual live/local comparisons have passed. This initial source inventory itself still provides no execution coverage.
